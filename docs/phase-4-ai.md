## Global spending and rate controls

A platform-wide switch and UTC monthly reservation ceiling now guard every AI reservation before inference. Global and per-person attempt ceilings span all clubs. Reservations take a global lock before the existing club lock, and an over-budget attempt rolls back its ledger insertion. Failed/interrupted reservations remain charged conservatively. Platform Owners with MFA configure these controls through a named function; changes have append-only history and browser sessions cannot update tables directly. The underlying tenant-only reservation function is no longer callable by authenticated users or the runtime role. Real migrations default global AI off with a zero-dollar ceiling; synthetic tests explicitly enable their isolated fixtures. This lock favors correctness for the initial scale; throughput/load acceptance remains pending.

## Read-only aggregate analytics assistant

Eligible club managers can preview a fixed SQL dashboard projection for all accessible seasons or one verified club season. Only allowlisted integer metrics are included; names, IDs, evidence, attendance reasons and mentor caseloads are excluded. A configurable minimum cohort defaults to five, and smaller nonzero counts are suppressed. Aggregation and suppression are not guarantees of anonymity and still require applicable privacy review.

The exact outbound values appear before the user confirms provider transmission. A hash binds inference to the freshly rechecked scope, metrics and cohort policy; changed data requires a new preview. The model receives no query tool or SQL execution path. Typed replies may cite only projected metrics and cannot contain mutation/tool fields. UI pairs comments with original server values and warns that a snapshot establishes neither trends nor causes. Semantic accuracy and live-provider acceptance remain pending.

## Usage reporting

The providers page now shows full current-UTC-month reservation totals, estimated token costs, attempt outcomes and daily totals. Reporting is independent of the recent-100-attempt table. Eligible managers see their club; other eligible staff see only their own attempts. Platform Owners additionally see platform-wide totals. Internal aggregation helpers are not callable by browser/runtime roles. Tests use more than 100 attempts and check foreign-club, personal and global scope. A configurable club dashboard warning threshold defaults to 80 percent and is also used for that manager's platform warning display. Warnings appear in-app; external billing alerts and reconciliation/monitoring operations remain release work.

## Bounded curriculum retrieval

The rules assistant loads up to 1,000 approved-version requirements, ranks complete excerpts by deterministic word overlap and stable ID ties, and includes at most 40 within a 22,000-character serialized prompt. Oversized versions or metadata fail before inference; no excerpt is cut mid-record. Responses disclose selected and available counts and may cite only selected requirement IDs. This is lexical retrieval, not semantic search or exhaustive policy review. General rule settings, cross-document conflicts, retrieval relevance and prompt-injection/answer-quality evaluation remain unfinished acceptance work.

## Human-reviewed task suggestions

Managers start from a participant's current-level Record Book requirement. The server checks active consent, approved rule version and season/level match before inference. Only requirement text, source citations and level are sent; identity and human-entered due date stay local. Strict output permits title/instructions only. A private proposal records exact scope and payload; no task exists yet. Human review creates an idempotent staff-only task draft through the existing task validation function, rechecking consent and curriculum scope. Assignment remains separate. Rejection creates no task, and points/completion are unaffected. Runtime credentials cannot call proposal approval functions. Five SQL cases cover authorization, altered payloads, direct-update denial, consent withdrawal, idempotency, foreign requirements, forbidden fields and rejection. Live-provider safety/semantic quality remains pending.
